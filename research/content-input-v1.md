# コンテンツ入力・生成仕様 v1

この版は、研究用の完全な履歴DBや条件割付を導入せず、展示の生成体験で本人の経験を保つための仕様である。

## 入力

導入は「日常の違和感や、うまく説明しにくい経験」。妖怪については質問しない。

1. `experience` — どんなことがありましたか（必須・自由記述）
2. `location` / `activity` — 場所と、その時していたこと（同一画面・任意）
3. `salientFeature` — 特に気になった点（任意）
4. `recurrence` / `duration` / `change` — 反復、1回の持続、変化（反復と持続は分離）
5. `hasExplanation` / `explanation` — すでにある本人の説明。説明欄は「ある」の時だけ表示する。

空欄は不明であり、生成モデルが本人の発言として補完しない。原文は検索、概念、画像、物語の全プロンプトへ渡す。本人が日常的な説明を示した場合、妖怪は事実原因でなく創作上の表現として扱う。

## 交渉と画像

概念の名前・性質・短い物語は、画像生成前に本人が編集できる。残したい点と違う点を保存し、テキストの編集だけでは画像を生成しない。概念の編集は前後の値をsessionStorageに残し、直前の編集を取り消せる。完成画像にも同じ二つの反応欄を表示し、物語だけは画像を作り直さず保存できる。画像上限後に完成画面へ戻る操作と、物語の保存操作は、最終採用した名前と文章をDBへ同時に同期する。

画像の予算は、1体験あたり初回1回と明示的な作り直し2回、計3試行である。失敗も1試行として数える。戻る、再表示、再読み込みで自動的に新たな試行を行わない。画像APIは隠れた再試行や高価格モデルの探索を行わず、明示操作1回を1回の試行として扱う。以前の画像は、新しい作り直しが失敗しても状態から削除しない。画像上限後も完成画面へ戻れる。

## 今回の範囲

伝承は実アーカイブ検索結果だけを出典付きで表示し、取得できない場合に作り話を伝承として提示しない。現代参加者の類似検索、研究用のランダム条件、QRの追跡基盤、完全なDB操作履歴は次段階に分ける。
